# مراجعة أمان زبيد

هذه مراجعة تنفيذ واختبارات محددة، وليست شهادة تدقيق اختراق أو اعتماد نشر تجاري.

## ضوابط منفذة ومختبرة

- التحقق من جلسة الخادم ومن أدوار الشركة وعضويتها في كل مدخل Server Functions، بما فيه وظائف الوجه. رفض companyId لشركة أخرى قبل قراءة مخزنها أو تنفيذ إجراء على أجهزتها.
- فصل مخازن واعتمادات الشركات وسياق العمليات غير المتزامنة، ومنع تداخل العمل المتزامن في الاختبارات. رفض ملف state يحمل companyId مخالفاً للسياق.
- العنوان IPv4 خاص/مسموح ومسجل، دون طلبات جهاز اعتباطية أو إعادة توجيه تخالف ضوابط SSRF القائمة. منع مشاركة عنوان جهاز ومنفذه بين شركتين مع تسلسل فحص الملكية والحفظ.
- الجلسة HttpOnly وSameSite Strict، وحماية Origin/CSRF، وعدم اعتماد أعلام sessionStorage القديمة كصلاحية. حساب الشركة لا يستخدم مسار Hik-Connect القديم غير المقيد بالشركة؛ هذا المسار محصور بمسؤول النظام.
- كلمات مرور الأجهزة في RAM أو خزنة AES-GCM على الخادم. لا توجد كلمة مرور في localStorage. كلمة مرور حساب البرنامج مخزنة PBKDF2 مع salt، ولا تُحفظ مدخلات كلمات المرور في كتالوج الشركات.
- تسجيل الوجه: صلاحية مسؤول، تأكيد قصير العمر مرتبط بالجلسة والشركة والموظف والجهاز، قفل عملية، تحقق الهوية والقدرات، ثم قراءة نتيجة. الصور والقوالب لا تدخل سجل التدقيق أو public أو localStorage.
- التشخيص يسجل طلباً وResponseStatus منقّيين، ولا يسجل Digest Authorization أو كلمة مرور أو matchList بأسماء الموظفين. رفض HTTP 400 يبقى فشلاً، مع الحفاظ على بيانات الفترة القديمة دون تزوير وقتها.
- سجل تدقيق للأعمال الإدارية على الجهاز، وسجل كتالوج للشركات والفروع والحسابات. لا توجد كتابة حية على جهاز Hikvision ضمن اختبارات التسليم.
- الخادم المستقل حجب المسارات الخاصة/النسخ/ملفات bak بـ403 في اختبار HTTP. حماية Vite الإضافية الموجودة في `docs/access-center-vite-guard.patch` لم تُطبق على إعداد الخدمة الحية لتجنب إعادة تشغيلها دون اعتماد؛ نتائج staging والخادم المستقل لا تُقدّم كدليل على تطبيق هذا التعديل على خدمة 8080.
- فحص حزم البناء يمنع تضمين `.env` أو state/companies/credential أو keystore، ويقارن الأسرار البيئية المتاحة ببناء الخادم دون طباعة قيمها. العدد ونطاق الفحص مثبتان في `ZUBAYD_CHANGES.json`؛ لا يشمل ذلك أسراراً غير متاحة للجلسة.

## ضوابط حزم المنصتين

- Android يمنع cleartext وmixed content ويتحقق من شهادات HTTPS ويقصر التنقل على أصل الخادم المختار، مع تعطيل وصول file:// والجسر JavaScript العام. الكاميرا باستخدام ملفات خاصة وإذن مؤقت، والتصدير عبر رسالة ذات nonce وقناة مربوطة بأصل الخادم ونافذة حفظ يختارها المستخدم.
- APK تجريبي debuggable، ولا يوزع كنسخة إنتاج. لم يوجد هاتف متصل لاختبار التنفيذ الفعلي.
- Windows يجهز renderer مع sandbox وcontextIsolation وNodeIntegration معطل، وIPC يتحقق من الإطار/الأصل. عمليات الصيانة تتطلب إعادة اعتماد مسؤول النظام ومحدودية محاولات وتأكيداً. تشغيل الخادم لا يرث اعتمادات التطوير؛ يستعمل قائمة بيئة محدودة ومفتاح خزنة محمياً بواسطة نظام التشغيل.
- النسخ AES-256-GCM ومفتاح مشتق بـscrypt، وفحص سلامة ومحتوى ومسارات قبل الاستعادة. استعادة مرحلية مع الاحتفاظ بالمجلد السابق. اختُبر المنطق على بيانات مؤقتة مع بديل safeStorage للاختبار؛ **لم يُختبر DPAPI وIPC وElectron فعلياً** لغياب Runtime تنزيل صالح.
- توقيع Windows التجاري والتثبيت النظيف غير مكتملين. لم تُفتح منافذ أو Firewall، ولم يُوقف SSH أو Tailscale.

## حدود تستلزم اعتماداً قبل الإنتاج

1. مراجعة حساب مسؤول النظام القديم، واسم شركة التوافق، وعضويات العملاء، ومجلد خاص وACL في Windows. حقول البيانات الشخصية في مخزن JSON خاصة على الخادم لكنها ليست قاعدة بيانات مشفرة بالكامل.
2. تشغيل خادم واحد لكل مخزن. الأقفال والتخزين الحاليان داخل عملية واحدة، ولا يكفيان لعدة عمليات/خوادم على الملفات نفسها. تكرار الجهاز بعنوان بديل/وكيل يحتاج سياسة ملكية إضافية بالهوية المادية قبل بيئة شبكات متداخلة متعددة العملاء.
3. HTTPS موثوق على الخادم قبل استخدام الهاتف للعمليات الحساسة، وتأمين مسار الجهاز حسب قدراته. HTTP Digest لا يشفر محتوى أحداث/صور HTTP؛ لا يساوي HTTPS. لا يرسل PIN عبر HTTP غير المحمي.
4. عدم إتاحة خادم Vite التطويري للعموم، ومراجعة patch الحماية الجاهز عند اعتماد إعادة تشغيل الخدمة. المنتج الموزع يستعمل حزمة الخادم المستقلة.
5. الاختبارات الحقيقية المؤثرة على الجهاز تتطلب إذناً جديداً واضحاً وموظف اختبار محدداً. لا يوجد ادعاء بأن محاكاة upload/readback تثبت عمل كل Firmware.

## المراجع

مراجع Hikvision المحلية في `docs/codex-access-pack/REFERENCES`، ومراجع capability المكتوبة في الشيفرة والتقارير السابقة. Push وISAPI وHik-Connect عقود مستقلة. يؤكد [إصدار Hikvision V1.2.7 للسلسلة](https://assets.hikvision.com/prd/public/all/files/202308/DS-K1A340%20Series%20MinMoe%20Terminal%20V1.2.7_build230609%20Release%20Note.pdf) اختلاف عتاد طرازات F؛ لا يُعرض مستشعر إصبع على WX.

نمط العزل وIPC يستند إلى [إرشادات أمان Electron](https://www.electronjs.org/docs/latest/tutorial/security)، ومعالجة TLS تستند إلى [توثيق WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient). إعداد عدم حذف بيانات المستخدم في المثبت يتبع [خيارات NSIS في electron-builder](https://www.electron.build/docs/nsis/). هذه مراجع تصميم؛ ليست دليلاً على اختبار مثبت لم يُنتج.
