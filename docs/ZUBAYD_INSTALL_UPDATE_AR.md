# زبيد — التثبيت والبناء والتحديث

## ملفات هذه النسخة

- APK تجريبي: `releases/android/Zubayd-debug.apk`.
- بصمته الرقمية: `releases/android/SHA256SUMS.txt`.
- مشروع Android: `android`.
- مشروع Windows: `desktop`.
- الخادم المستقل: `dist-server/server/index.mjs`.
- **Setup.exe غير موجود في هذا التسليم؛ لا يوجد مثبت Windows بديل صوري.**

## Android للمستخدم

1. خذ APK من المسؤول وتحقق من SHA256SUMS. التوقيع الحالي تجريبي وليس نسخة متجر.
2. بعد التثبيت أدخل عنوان **HTTPS** لخادم شركتك دون مسار إضافي، ثم «اختبار الخادم والاتصال».
3. إذا كان العنوان HTTP فقط، اطلب تجهيز شهادة واتصال موثوقين. لا تعطل فحص الشهادة. Tailscale خيار اتصال يضبطه المسؤول بموافقة، وليس عنواناً ثابتاً داخل التطبيق.
4. سجل الدخول بحساب البرنامج واختر الشركة. اختيار صورة الوجه لا يرفعها حتى تؤكد التسجيل. الكاميرا تحتاج الإذن عند الطلب؛ المعرض بديل.
5. في التقرير اختر CSV أو Excel أو PDF وحدد مكان الحفظ الأصلي. حد تصدير الملف عبر الغلاف 8 ميجابايت. استخدم فترة أصغر للملفات الأكبر.

لا يوجد هاتف/محاكي متصل لاختبار التثبيت في بيئة التطوير الحالية. اختبارات المتصفح لا تعوض تجربة الكاميرا وWebView على هاتف.

## البناء للمطور

من جذر المشروع:

```powershell
npm run typecheck
npm run test:access
npm run test:zubayd
npm run build:app
npm run build:android
```

`build:android` يستخدم أدوات Android SDK API 36.1 وbuild-tools 36.1.0 وJDK17+ الموجودة. يمكن تحديد `ANDROID_HOME` و`JAVA_HOME` إذا اختلف المسار. لا يحوي التوقيع التجريبي مفاتيح نشر. مفتاح debug المحلي في النسخة الاحتياطية غير مخصص للنشر.

لبناء APK/AAB للإصدار، يلزم Gradle المتوافق مع Android Gradle Plugin 8.13، وتنزيل تبعياته، وشهادة الناشر. لا يوجد Gradle Wrapper محمل ضمن هذه النسخة. من بيئة Gradle مجهزة:

```powershell
gradle -p android :app:assembleRelease
gradle -p android :app:bundleRelease
```

تقرأ إعدادات توقيع الإصدار من `ZUBAYD_ANDROID_KEYSTORE` و`ZUBAYD_ANDROID_STORE_PASSWORD` و`ZUBAYD_ANDROID_KEY_ALIAS` و`ZUBAYD_ANDROID_KEY_PASSWORD`. أدخلها من مدير أسرار بيئة البناء؛ لا تحفظ كلماتها في المشروع أو المحادثة. بدون إعداد التوقيع لا تُسمّ النسخة موقّعة للنشر. لا تغيّر appId بعد إصدار تطبيق للعملاء دون خطة ترحيل.

## Windows للمطور

Node مطلوب على **جهاز البناء** الآن. المثبت النهائي، بعد بنائه، يستخدم Runtime Electron داخل الحزمة ولا يُفترض أن يطلب Node منفصلًا من المستخدم. لم يُثبت ذلك بتجربة مثبت لأن تنزيل الأدوات تعذر.

```powershell
node scripts/zubayd-install-desktop.mjs
npm run build:windows
```

الأداة الأولى تنزل Electron وelectron-builder وتثبت نسخها المحددة في بيانات حزمة desktop عند اكتمالها. توقفت المحاولات الحالية بسبب TLS، فملفات الاعتماد وRuntime اللازمة للتغليف لم تكتمل. عالج بيئة الشبكة/Node أو وفر الأدوات من مصدر رسمي موثوق ثم أعد البناء؛ لا تستخدم `strict-ssl=false` أو تعطيل التحقق من الشهادات.

المخرج المتوقع بعد نجاح البناء: `releases/windows/Zubayd-Setup-1.0.0.exe`. هذا **مسار متوقع وليس ملفاً موجوداً الآن**. يلزم توقيع الناشر واختبار جهاز Windows نظيف قبل التوزيع.

لإنتاج الخادم واختباره منفصلًا على جهاز التطوير دون ترحيل بيانات:

```powershell
npm run build:windows:server
node scripts/zubayd-standalone-smoke.mjs
```

لا تستخدم `npm run build` بغرض التحقق فقط: السكربت القديم يشغل ترحيل قاعدة بيانات بعد البناء. استخدم `build:app`، أو `build:windows:server` حسب الهدف.

## أول تشغيل Windows عند توفر المثبت

1. أكمل التثبيت ثم افتح اختصار زبيد.
2. اختر شركة العميل واسم المدير واسم الدخول وكلمة مرور من 12 حرفاً على الأقل ومجلداً **فارغاً خاصاً** للبيانات. لا تختَر مجلد الإنتاج الحالي أو مجلداً عاماً مشتركاً.
3. يبدأ الخادم على هذا الكمبيوتر فقط. من قائمة التطبيق «اتصال الهاتف وHTTPS» أدخل حساب المسؤول، وعنوان الاستماع والمنفذ، واسم الخادم وشهادة PEM ومفتاحها، ثم وافق واكتب «تغيير اتصال زبيد».
4. لا يفتح البرنامج Firewall أو يغير Tailscale تلقائياً. مسؤول الشبكة يعتمد المسار وقواعد الوصول والشهادة. يجب أن يطابق DNS/عنوان الشهادة الخادم ويمكن الوصول إليه من الكمبيوتر والهاتف.
5. لا تتغير بيانات البصمة خلال الإعداد. افتح الشركات ثم الأجهزة وأدخل اعتماد الجهاز داخل النموذج الآمن.

## النسخ والتحديث والاستعادة

- قائمة Windows «النسخ الاحتياطي والصيانة» تحتاج حساب مسؤول النظام وكلمة مرور مستقلة للنسخة. اختيار إنشاء نسخة يتضمن توقفاً قصيراً **لخادم التطبيق وحده** لضمان اتساق ملفات جميع الشركات، ثم إعادة تشغيله.
- النسخة AES-GCM محمية بكلمة مرور، وتشمل مفتاح الخزنة داخل المحتوى المشفر حتى يمكن استعادتها على تثبيت آخر. احفظها وكلمة مرورها في مكانين مستقلين. لا تُحفظ ملفات النسخ داخل مجلد بيانات التطبيق.
- الاستعادة: افحص النسخة أولًا، ثم راجع الأعداد واكتب «استعادة بيانات زبيد». تُجهز الملفات في مجلد مرحلي، ويُحتفظ بالمجلد السابق كاملًا بجوار المجلد الحالي، وتفشل العملية دون تطبيق عند فشل المصادقة/سلامة النسخة. بعد النجاح سجل الدخول بحساب النسخة المستعادة.
- مجلد البيانات السابق ليس أرشيفاً مشفراً جديداً؛ احمه بنفس ACL الخاصة بمجلد العملاء. احتفظ به حتى تتأكد من القبول، ثم طبق سياسة احتفاظ معتمدة خارج جلسة التطوير.
- قبل التحديث صدّر نسخة مشفرة واختبر استعادتها في بيئة منفصلة. حدّث ملفات البرنامج مع إبقاء مجلد البيانات. إعداد NSIS لا يحذف بيانات العملاء عند إلغاء التثبيت. لم يُختبر تحديث/إلغاء تثبيت فعلي حتى يتوفر Setup.exe.

## استبدال الهوية المؤقتة

ضع الشعار الرسمي داخل `public` واضبط `logoSrc` مثل `/brand/official-logo.png` في `brand.config.json`. عدّل الألوان والخط بالاعتماد على ملف الهوية الرسمي ثم شغّل `node scripts/zubayd-assets.mjs` وأعد بناء حزم المنصتين. المولد يحافظ على نسبة أبعاد الشعار. أسماء العملاء وأجهزتهم لا تتغير بتعديل هوية المالك.
