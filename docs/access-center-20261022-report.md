## الوظائف المنفذة

### الواجهة والتشغيل

واجهة عربية RTL بأقسام: لوحة التحكم، المستخدمون، الأبواب، وسائل التحقق، الصلاحيات والجداول، الحضور، الأحداث والاستثناءات، الأجهزة والتشخيص، التدقيق، الإعدادات، وHik-Connect والملفات. قائمة جانبية للكمبيوتر وتنقل سفلي للموبايل، نماذج قابلة للإلغاء، رسائل فشل واضحة، ومؤشر تقدم السحب.

احتُفظ بتكامل Hik-Connect والاستيراد اليدوي داخل قسم مستقل؛ ملفات التكامل السحابي التي كانت معدلة قبل المهمة بقيت كما كانت مقارنة بالنسخة الاحتياطية. بيانات الواجهة السابقة لا تُستبدل ببيانات المحاكي، ولا تُنسخ بيانات اختبار إلى مخزن التطبيق الحي.

### الأجهزة والمزامنة

- اتصال Digest من الخادم فقط، مع MD5 وMD5-sess وSHA-256 وSHA-256-sess و`qop=auth`. أُلغي التخفيض التلقائي إلى Basic.
- تسجيل أجهزة بعناوين IPv4 خاصة أو Tailscale وإضافتها إلى allowlist، ومنع عناوين DNS والعناوين العامة وloopback وlink-local والتحويلات HTTP redirects.
- قراءة معلومات الجهاز والقدرات والقنوات والساعة وNTP وDST دون تغيير إعداداته. مصفوفة قدرات ثلاثية: supported / unsupported / unverified، مع المسار والمرجع والحدود ونتيجة الفحص.
- استجابة `statusCode=1` وحدها لا تثبت قدرة، ولا تُقبل صفحة HTML بوصفها عقد capability. لا تُستنتج قنوات الأبواب من الحد الأقصى النظري؛ تُقرأ القنوات الفعلية من حالة الجهاز.
- سحب المستخدمين وجميع أصناف الأحداث بصفحات مستقلة، حفظ كل صفحة، منع تكرار الأحداث لكل جهاز/رقم تسلسلي/وقت أصلي، وإظهار النتائج الجزئية عند الفشل. إعادة السحب لا تضاعف السجلات، وغياب شخص عن صفحة لا يحذفه تلقائياً.
- Polling فعلي بمؤقت في عملية الخادم، بفاصل لا يقل عن 60 ثانية، منع تداخل المهام، واسترجاع فترة متداخلة مع منع التكرار وbackoff عند الفشل. يبدأ المؤقت عند أول طلب مصادق عليه بعد تشغيل الخادم؛ يستمر دون إبقاء صفحة المتصفح مفتوحة ما دامت عملية الخادم تعمل.
- اختبار اتصال ببيانات جديدة لا يمحو بيانات الاتصال العاملة عند فشله. تغيّر الرقم التسلسلي في العنوان نفسه يوقف الربط لحماية التاريخ.

### المستخدمون ووسائل التحقق

- إضافة وتعديل المستخدم، صلاحية دائمة أو محددة، وإنهاء الصلاحية للتعطيل. **`Valid.enable=false` تعني صلاحية دائمة، وليست تعطيل المستخدم.**
- حذف مستخدم واحد فقط بالمعرّف، مع شرح إزالة وسائله، تتبع اكتمال الحذف، وبقاء أحداث البرنامج التاريخية.
- معاينة CSV/XLSX حتى 50 موظفاً، كشف الحقول الناقصة والأرقام الموجودة والمتكررة، تأكيد مكتوب قبل الإرسال، وتدقيق نتيجة كل صف في الدفعة. لا توجد إعادة تلقائية لكتابة فاشلة.
- قراءة الكروت بصفحات، إضافة كارت وإلغاء كارت محدد. فحص رقم الكارت وملكيته قبل المعاينة ومجدداً قبل التنفيذ، ثم بحث دقيق لإثبات النتيجة حتى إن تجاوزت قائمة الموظف صفحة واحدة.
- عرض أعداد الوسائل عند توفر القراءة الموثقة دون استخراج قوالب الأصابع أو إسناد عدد مكتبة الوجوه بأكملها إلى شخص واحد.
- تعيين PIN للكتابة فقط مقيد بحدود الجهاز وبـHTTPS موثوق؛ يظل معطلاً مع اتصال HTTP الحالي. لا تُعاد قيمته إلى المتصفح ولا تُكتب في audit.
- استجابة الجهاز المقبولة وحدها لا تسجل نجاح تعديل بيانات المستخدم؛ تُطابق قراءة الاسم وفترة الصلاحية بعد الكتابة.

### الأبواب والصلاحيات

- «إضافة باب» ينشئ اسماً وموقعاً وملاحظات لقناة عتاد موجودة ومثبتة. لا ينشئ قناة فعلية.
- عرض وضع القناة المقروء، وأوامر open / close / alwaysOpen / alwaysClose فقط عند إثبات القناة والأمر. تأكيد Admin من خطوتين مع تحديد الأمر والقناة وتحذير الوضع المستمر.
- قبول الجهاز للأمر يسجّل قبولاً بروتوكولياً، ولا يدّعي حركة القفل الميكانيكية.
- ربط مستخدم بأبواب وقالب موجود بعد قراءة القالب وجدوله الفعالين. التأكيد يوضح استبدال قائمة الأبواب الحالية، وتُراجع الأبواب وأرقام القوالب بعد الكتابة.
- تشخيص منع الدخول اعتماداً على قائمة المنع وفترة الصلاحية وإذن الباب والخطة المقروءة؛ لا يدّعي قرار سماح نهائياً إذا لم تُقرأ كل شروطه.
- حفظ خطط أسبوعية محلية وقراءة قالب وجدول فعليين. تطبيق خطة على جدول قالب موجود يحتاج إثبات الحدود، وقراءة سابقة ومعاينة وتحذير أثر الجدول المشترك وتأكيداً مكتوباً. تقسيم الفترة الليلية إلى يومين، ورفض التداخل وتجاوز حدود الفترات.
- يُحفظ ملف خاص `schedule-before-*.json` قبل أول كتابة للجدول، ويُرفض التنفيذ إذا تغير الجدول منذ المعاينة، وتُطابق إعادة القراءة. لا توجد استعادة تلقائية قد تمس صلاحيات حقيقية.

### الحضور والأحداث

- حفظ timestamp والـoffset الأصليين والرقم التسلسلي وmajor/minor والموظف والباب والمصدر؛ أحداث 2015 تبقى في 2015 وبإزاحتها الأصلية.
- تصنيف منفصل للتحقق الناجح والمرفوض والإنذارات والنظام وغير المعروف. أحداث النظام وفتح الباب ليست حضوراً. تصحيح دلالات التحقق الموروثة محفوظ، ومنها minor 38 لبصمة الإصبع و77 للموظف مع الوجه، واستبعاد 113 الخاص بالقائمة السوداء.
- ورديات وأيام عمل وسماح تأخير وانصراف مبكر، وردية ليلية، عطلات محلية وإجازات، غياب وانصراف مفقود، ودمج التحقق المتقارب. لا تُحتسب مدة 19 ساعة كدوام عادي؛ تُرفع للمراجعة وتُترك المدة المحسوبة فارغة.
- تقارير فترة/أسبوع/شهر مع CSV وExcel وPDF، وفلاتر للأحداث وتصدير وملاحظات مراجعة تحفظ الأصل.

## الأمان والتخزين

- مخزن خادم مستقل بإصدار schema واضح، كتابة ذرية و`state.previous.json`، وقيود تمنع الإسقاط الصامت للأحداث عند بلوغ الحد. لا توجد ترحيلات إنتاجية.
- المسار الافتراضي **`%LOCALAPPDATA%\SKYLINE\access-control`** خارج جذر Vite. أعدت أداة bootstrap تقييد ACL لمستخدم Windows الحالي ونقلت حالة الحساب السابقة مع تحقق تطابقها، واحتفظت بالنسخة الأصلية دون حذف.
- كلمات مرور حسابات التطبيق مجزأة PBKDF2؛ الحساب السابق محفوظ دون وضع كلمة مروره في الكود الجديد.
- أسرار الجهاز في ذاكرة الخادم 8 ساعات افتراضياً. الحفظ الدائم يتطلب SKYLINE_VAULT_KEY خارج المستودع، ويستخدم AES-256-GCM مع nonce ووسم تحقق وربط بالمعرف. لا تُخزّن كلمة المرور في localStorage ولا تظهر في snapshot أو audit أو سجلات الاختبار.
- جلسات الخادم في الذاكرة 8 ساعات، والدور يُحل من الحساب في الخادم، وليس من sessionStorage. حظر Origin غير المطابق، والتحقق من المدخلات والهوية والحدود قبل العمليات.
- سجل التدقيق يذكر الفاعل والوقت والعمل والهدف المحدد والنتيجة؛ هدف الكارت/الموظف/الباب محفوظ دون PIN أو كلمة مرور أو قالب بيومتري.
- هذا التخزين والـpolling مناسب لعملية Windows واحدة. تشغيل موزع أو Serverless يحتاج مخزناً وعاملاً دائمين منفصلين.

### حماية الملفات على الخدمة الحية: بانتظار موافقة

اختبار حظر `.skyline-private` و`.codex-backups` و`.git` وملفات `.bak` نجح 403 على 8092، وأضيف middleware للإنتاج. **لم أعدّل vite.config.ts الحي** لأن ذلك قد يعيد تشغيل Vite، والتكليف يشترط موافقة قبل التأثير على الخدمة. طُلبت الموافقة أثناء التنفيذ ولم تصل إجابة.

التعديل المحدد جاهز في `docs/access-center-vite-guard.patch`. لا أدّعي أن حظر الملفات هذا مفعل الآن على 8080؛ فحص HEAD لمسار اختبار غير موجود أعاد 404، ولم تُجلب أي نسخة احتياطية أو كلمة مرور من HTTP. تحتوي النسخ القديمة على كود قديم حساس، ولذلك تفعيل الحماية خطوة متبقية مهمة قبل اعتبار تأمين خدمة التطوير مكتملاً.

## التشغيل والخطوات المتبقية

1. افتح `/access` بحساب البرنامج السابق، ثم «الأجهزة والتشخيص» وأدخل حساب جهاز البصمة واضغط «اتصال وفحص بالقراءة فقط». هذا لا يغير بيانات الجهاز. بعد نجاحه يمكن سحب المستخدمين والأحداث، مع اختيار فترة 2015 الأصلية للأحداث القديمة.
2. لاختبار طرفية آمن: `npm run probe:hikvision -- --credentials-file <مسار ملف JSON خاص خارج المشروع>`، ومحتواه username وpassword. البديل HIKVISION_USERNAME وHIKVISION_PASSWORD في بيئة الخادم. لا تضع كلمة المرور في نص أمر أو ملف داخل Git. الأداة ترسل GET وعمليات البحث POST فقط.
3. يمكن إعادة الاختبارات بالأوامر أعلاه. استخدم `npm run build:app` للبناء دون ترحيل؛ أمر build القديم ما زال يتبعه db:migrate ولم أشغله.
4. تفعيل patch حماية Vite يحتاج الموافقة المطلوبة لإعادة تحميل 8080. تغيير الصفحة الرئيسية إلى المركز يحتاج الموافقة المطلوبة لتغيير route؛ بقي `/` كما كان وأضيف رابط واضح إلى `/access`.
5. لا يمكن الجزم بدعم/عدم دعم الوجه أو جمع الإصبع أو باب فعلي على هذا الموديل قبل الفحص المصادق عليه. رفع/إلغاء صورة وجه وجلسة جمع الإصبع معطلان بسبب غياب عقد وحدود مكتبة/قارئ ونقل آمن مثبتين. لا توجد أزرار مفعلة تدعي تنفيذها.
6. كتابة مجموعات عطلات الجهاز أو تهيئة NTP وPush وOpenAPI لم تُنفذ؛ يلزم إثبات القدرة والعقد/الاعتمادات ثم موافقة على التغيير الحقيقي. العطلات والإجازات المحلية وتقارير الحضور تعمل دون تعديل صلاحيات الجهاز.
7. كل تجربة كتابة حقيقية أو فتح باب أو حذف أو تعديل إذن دخول تتطلب موافقة صريحة وبيانات اختبار مناسبة؛ نجاح المحاكي لا يثبت قبول firmware الحقيقي لهذه العمليات.
8. للاسترجاع: احفظ نسخة الحالة الحالية أولاً، وقارن الملفات مع النسخة الاحتياطية. لا تُستعد state أو جداول الجهاز أو ملفات الخدمة الحية فوق بيانات أحدث دون مراجعة وموافقة. ملفات schedule-before توفر المادة اللازمة لمراجعة استعادة جدول بعينه.

**الخلاصة:** التنفيذ البرمجي واختبارات المحاكي والمتصفح والبناء متاحة وموثقة. الوصول الحقيقي إلى عنوان البصمة وDigest مؤكدان الآن، وإتمام السحب الحقيقي الجديد ومصفوفة قدرات الجهاز ينتظران كلمة مروره. نشر حماية Vite وتغيير الصفحة الرئيسية ينتظران التأكيدين المطلوبين بموجب التكليف.
